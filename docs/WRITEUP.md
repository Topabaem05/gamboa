# DACON 선박 식별 대회 작업기

입항 기록 한 줄을 공식 선박 카탈로그(78,595척)의 `vessel_id` 하나에 매칭하는 대회입니다.
이 글은 첫 제출(0.7531)부터 현재(리더보드 0.99)까지 무엇을 했고, 무엇이 통했고,
어디서 아직 점수를 잃고 있는지를 정리합니다.

대회: https://dacon.io/competitions/official/236771/overview/description

## 1. 문제와 평가

- **질의(train/test)**: `vessel_name`(한글 음차 또는 오타가 섞인 영문), `call_sign`(해시),
  `gross_tonnage` / `international_gross_tonnage`, `flag_name`(한글), `vessel_type`(한글), `arrival_year`.
- **카탈로그**: `vessel_id`, 영문 `vessel_name`, 영문 `flag_name`·`vessel_type`, 총톤수, 재화중량 등.
- **평가**: `0.7 × 한글 이름 행 정확도 + 0.3 × 그 외 행 정확도`. 한글 행이 약 10%뿐이라
  **한글 오답 1행이 영문 오답 1행보다 약 20배 비쌉니다.**
- **제출 방식**: 코드 제출. 채점 서버가 `script.py`를 실행해 비공개 `data/test.csv`로
  `output/submission.csv`를 만듭니다. 레이아웃은 배포된 `baseline_submit.zip`과 같습니다.

데이터에서 확인한 사실:

| 항목 | 값 |
|---|---|
| train 행 / 선박 수 | 12,222 / 5,851 (선박당 약 2.1행) |
| 한글 이름 행 비율 | 9.7% (한글 이름 382종) |
| 영문 질의 중 오타 없는 행 | 약 62% (나머지는 삭제·문자중복·전치 1~3개) |
| 질의 총톤수가 카탈로그와 정확히 같은 행 | 49% (최소 갭 기준 최대 8.75%) |
| 한 선박의 질의명이 행마다 다른 경우 | 0.2% (질의명은 선박 단위로 고정) |

## 2. 점수 변천

| 버전 | 핵심 변경 | 미학습 선박 CV (weighted) | 리더보드 |
|---|---|---|---|
| v1 | train 정답 하드코딩 + 베이스라인형 RandomForest | 0.755 | **0.7531** |
| v2 | 한글·영문 공통 음운 클래스 비교 | 0.98 (fold 0~2) | 미제출 |
| v5 | 후보 전체 학습 HistGradientBoosting, 개명 규칙 | 0.998 | 미제출 |
| v6 | 오류 10건을 에이전트 10개가 분석해 규칙·피처 통합 | 1.000 (5-fold 전부) | **0.99** |
| v7 | 한글 표기 변이 정규화 + 한글 증강 학습 | 검증 중 | 미제출 |

**v1의 교훈.** 첫 제출 점수가 미학습 선박 CV와 거의 같았습니다. 비공개 test의 선박은 train에
없다는 뜻이고, train 정답을 외우는 것은 test 점수에 기여하지 않습니다. 이후 모든 작업은
"처음 보는 선박을 이름·톤수·국적·선종만으로 찾는 매처"를 만드는 일이었습니다.

## 3. 매처 구조 (`model/vessel_matcher.py`)

1. **정답표(AnswerBook)**: train의 `call_sign`, 정규화된 이름 → `vessel_id`. 충돌 0건.
   미학습 선박에는 한 번도 발동하지 않음을 5-fold로 확인했습니다.
2. **음운 클래스 표현**: 한글과 영문을 같은 자음 클래스 문자열과 모음열로 바꿉니다.
   L/R, B/V, P/F, 연음 C·J·Z·S를 합치고, 영어의 자음 앞 R과 한글의 `르`를 떨어뜨리고,
   `케이에스→KS`처럼 철자로 읽은 약어를 풀고, `제N`·`No. N`·로마숫자를 번호로 맞춥니다.
   train 한글 쌍의 95%가 자음열 완전일치입니다.
3. **후보 검색**: 로마자·자음열·모음열 bigram/trigram(numpy bincount), 완전일치, 동일 톤수 전체,
   톤수 ±6% 창 안의 이름 상위, 마지막 단어 완전일치. 행당 약 140개 후보, 정답 포함률 100%.
4. **랭커**: 후보 전부를 학습 샘플로 쓰는 HistGradientBoosting. 68개 피처는 문자열 유사도
   (Levenshtein, OSA, n-gram), 토큰·숫자 일치, 톤수 갭, 한글 국적→영문 국적 및 선종 조건부
   확률, 선종별 톤수 분포, 후보 집합 안에서의 상대 순위입니다.
5. **검증된 규칙**: 15% 톤수 마스크, 마지막 단어 개명 규칙, 선단 자매선 제외, 카탈로그 유일 톤수,
   한글 모음 동률 해소, 이름 단서가 없는 개명 선박용 톤수·국적·선종 마스크, 완전 쌍둥이 동률 해소.
   각 규칙은 발동한 행에서 오류 0건일 때만 넣었습니다.

## 4. 오류 10건을 에이전트 10개로 분석 (v6)

v5의 미학습 오류 10건을 Opus 에이전트 10개에게 한 건씩 맡겼습니다. 각 에이전트는 사례 파일
(질의, 정답·오답 행, 피처 값, 상위 후보)을 받고, 규칙을 제안하면 정밀도를 직접 측정해 보고했습니다.

| 사례 | 원인 | 반영한 해결 |
|---|---|---|
| HAFNIA WREN → BW Wren | 정답이 후보에 없음(검색 누락) | 마지막 단어 포스팅 + 개명 규칙 보강 |
| CENTRAL PARK → Caifu Chao | 동일 톤수의 "X Park" 자매선에 끌림 | 선단 자매선 제외 규칙 |
| FAIRCHEM BRONCO → City Island | 카탈로그에서 유일한 톤수를 활용 못 함 | 유일 톤수 피처·규칙 |
| 펭슈하이 → Feng Xiu Hai | 자음열 동일 자매선, 모음만 다름 | 한글 모음 동률 해소 |
| DIIJLAH → Dijilah | 톤수 없음, 이름 동률 | 선종별 톤수 분포 피처·규칙 |
| BOW MERCURY / NAVIG8 VICTORIA / NOVA BREEZE / STREAM PACIFIC | 개명 선박이 공유 단어에 끌림 | 15% 톤수 마스크, 톤수·국적 거부 규칙 |
| 마스그라치 → Marsgracht | Maasgracht와 모든 컬럼이 동일 | 결정론적 쌍둥이 동률 해소 |

에이전트 한 명은 피처 이름 62개와 실제 열 64개가 어긋난 버그도 찾아냈습니다.

## 5. 채점 서버 오류: numpy 버전

첫 v6 제출은 채점 서버에서 아래 오류로 실패했습니다.

```
ValueError: <class 'numpy.random._pcg64.PCG64'> is not a known BitGenerator module.
```

HistGradientBoosting이 학습 때 만든 numpy 2 난수 생성기(`_feature_subsample_rng`)가
번들에 들어 있었고, 채점 서버의 numpy 1.x가 이를 읽지 못했습니다. 저장 전에 이 객체를 지우고,
채점 이미지와 같은 Python 3.11 / numpy 1.26.4 / scikit-learn 1.5.2 환경에서 번들을 다시 만들어 해결했습니다.

## 6. 리더보드 0.99: 어디서 잃고 있나

로컬 CV는 1.000인데 리더보드는 정확히 0.99였습니다.

**규모 추정.** test가 train처럼 한글 약 10%(300행)라면 한글 오답 1행은 0.0023점,
영문 오답 1행은 0.0001점입니다. 0.01을 영문만으로 잃으려면 약 90행이 틀려야 하는데 이는
로컬 성능과 맞지 않습니다. 한글이라면 4행 정도면 됩니다(예: 한글 4 + 영문 6 = 정확히 0.0100).

**CV가 낙관적이었던 이유.** 규칙과 음운 매핑을 train 전체의 오류를 보며 튜닝했기 때문에,
같은 데이터로 잰 1.000에는 과적합이 섞여 있습니다.

**재현 실험** (`experiments/`). fold 0·1 모델로 미학습 선박의 질의를 새로 만들어 평가했습니다.

| 시나리오 | 한글 정확도 | 영문 정확도 | 비고 |
|---|---|---|---|
| 원본 질의 | 1.000 | 1.000 | |
| 한글 재표기 (train에 실제 있는 변이) | **0.983 ~ 0.996** | – | 리더보드 손실 규모와 일치 |
| 국적 제거 | 1.000 | 1.000 | 국적 의존 없음 |
| 영문 새 오타 | 1.000 | 0.994 ~ 0.9995 | 생성기가 실제보다 가혹함 |

재표기에 쓴 변이는 학습 데이터에서 같은 영어 단어가 다르게 쓰인 예에서 가져왔습니다
(보이저/보이져, 파이오니아/파이오니어, 썬/선, 갤럭시/겔럭시, 스피리트/스피릿, 엠에스/엠에쓰,
톈진/텐진, 산동/샨동, 호 접미사, 띄어쓰기).

**찾은 실패 원인.**
- **정규화 누락**: `재7하나`가 선체번호로, `재이비유`가 JBU 약어로 인식되지 않았습니다.
- **모델 가중치**: `유니버설리더호`는 자음열이 Universal Leader와 완전히 같은데 Universal Winner를
  골랐습니다. 학습 데이터의 90%가 영문이라 모델이 한글에서는 믿기 어려운 모음 유사도에 과하게
  의존합니다. 톤수가 정확히 일치하지 않는 한글 질의(가스 프리웨이, 글로비스 커리지)도 같은 이유로 흔들립니다.

## 7. v7 수정 (검증 중)

- `재N`을 `제N`과 같은 선체번호로 처리합니다.
- 알파벳 철자 파싱 전에 ㅐ→ㅔ, ㅆ→ㅅ로 맞춥니다(재이, 에쓰, 캐이).
- 한글 학습 선박마다 표기 변이 3종을 만들고, 톤수도 train에서 관측된 (총톤수, 국제총톤수)
  노이즈 쌍으로 다시 뽑아 랭커 학습에만 추가합니다(2,709행). 정답표와 국적·선종 통계는 원래 행만 씁니다.

v6 대비 개선 폭은 fold 0·1에서 측정 중입니다. 평가용 재표기는 학습 증강과 다른 난수 시드로 만들지만,
변이의 **종류**는 같습니다. 따라서 test에 이와 다른 유형의 표기 변이가 있다면 이 검증으로는 잡히지 않습니다.

## 8. 재현 방법

```bash
pip install -r requirements.txt          # numpy<2, scikit-learn==1.5.2
# open.zip 의 csv 를 data/ 에 둡니다
python train.py                          # model/bundle.pkl, train 재현 100%
python evaluate_local.py --only-fold 0 --skip-replay
python experiments/stress.py --fold 0    # 새 노이즈 스트레스 테스트
python experiments/hangul_stress.py --fold 0
scripts/make_submission.sh               # submission.zip
```

채점 서버와 같은 번들을 만들려면 Python 3.11, numpy 1.26.4, scikit-learn 1.5.2 환경에서 `train.py`를 실행합니다.

## 9. 남은 일

1. v7을 fold 0·1에서 v6와 비교하고, 개선되면 5-fold 전체 검증 후 numpy 1.26 환경에서 재빌드해 제출합니다.
2. 한글 질의 전용 가중치가 필요한지 봅니다. 한글 행만으로 학습한 랭커나, 한글 행 가중치를 높인 학습이 후보입니다.
3. 리더보드 제출 시 v6 결과(0.99)와 비교해 한글 재표기 실험이 실제 손실을 설명하는지 확인합니다.
